# Dalaal Street

Dalaal Street is a browser-based market game for synchronized events and classroom activities. Players trade a fictional Indian stock market while a host controls the shared session. It is a learning simulation: prices and company news are generated by the game and are not live market data or investment advice.

## How the game works

- Each participant gets a device session and starts with ₹10,00,000 of simulated cash.
- Players can buy shares, sell shares they own, or open short positions. Prices move as the market simulation, news events, and participant trades update the shared market.
- A host can start, pause, and end a timed batch; set the next batch to 4–15 minutes; adjust market behavior; publish or schedule bulletins; and review participant sessions.
- The curated news library has 61 fictional bulletins: 12 economy stories, 3 for each of the 8 sectors, and 25 company stories for 25 different stocks. The remaining stocks still respond to their sector and economy stories. Hosts can select any mix of categories in Quick Access or News Studio, review the combined stock-by-stock estimate, and expand a headline for its individual effect before publishing.
- A new batch reset restores the market's starting stock prices as well as clearing its terminal sessions and published headlines.
- Host presence uses each device's last-seen heartbeat. A new batch resets participant portfolios without marking previously offline terminals as connected.
- Price movement is driven by 128 simulated traders with 16 distinct trading styles. The baseline volatility is 15% lower than the previous engine setting; hosts can still adjust volatility for an event.
- The audience wall shows the shared market without creating a participant account.
- The game includes an isolated practice market with the same three-second countdown, six-minute rounds, trading rules, news flow, settlement, and session report as a hosted game.
- Each player’s round report includes short, activity-based learning notes, badges tied to their choices, and their best and toughest realized closed trades.
- Host notes are stored with the shared game state and are available after sign-in from another device.

## Run locally

Requirements: Node.js 20.9 or newer and pnpm.

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

Open `http://localhost:3000`. Configure the environment values before using the shared market:

- `SUPABASE_URL`: Supabase project URL.
- `SUPABASE_PUBLISHABLE_KEY`: Supabase publishable (anonymous) API key.
- `MARKET_SIGNING_SECRET`: a long random secret used by the server to authorize market-state RPC calls.
- `HOST_PASSWORD`: password for `/host`.

The unversioned `/play` and `/audience` routes keep the original appearance; `/v1` is an alias for that look. `/v2` through `/v10` select Block Market, Market Mash, Paper Parade, Market Maze, Neon Nights ’88, Canopy Club, Blue Current, Sunday Signal, and School Recess ’92. Each version presents stocks and the market workspace differently while preserving the same company mark, symbol, name, price, return, mini-chart, sector, and position information. V7 uses a greenhouse garden, V8 a deep-sea expedition, V9 a nostalgic family-room broadcast, and V10 a nostalgic schoolyard. Every trading version keeps Buy, Sell, Short, and quantity controls inside the selected-stock chart workspace; selecting a stock updates that workspace without opening a dialog. All versions use the same market engine, accounts, controls, and news. Their trading and audience screens adapt to screen size and browser zoom, and their light/dark modes retain each theme's visual identity. The audience screen shows the Dalaal-10 closing level and return, strongest and weakest stocks, market breadth, short factual takeaways, the batch news feed, and all stock prices.

The practice market uses the same price and curated news simulation as a live round, but has its own state. It starts with a short countdown, runs for six minutes, closes positions at the end, and offers a new practice round. `/test/01` to `/test/12` use their own terminal logins. Legacy autonomous practice sessions are closed safely the first time the updated engine reads them.

During local development, open `http://localhost:3000/ui-preview` to compare the nine themed design directions. Preview market state stays in its own in-memory development store and cannot affect the shared live market. Preview routes return not found in production.

## Supabase setup

Apply `supabase/migrations/20261009000100_market_state.sql` to the project using the Supabase SQL Editor or Supabase CLI. The migration creates the private JSONB market-state table and its access-controlled RPC functions.

Add a row to `private.runtime_secrets` with the same value as `MARKET_SIGNING_SECRET`:

```sql
insert into private.runtime_secrets (id, market_signing_secret)
values (true, 'replace-with-the-same-random-secret')
on conflict (id) do update
set market_signing_secret = excluded.market_signing_secret;
```

Keep the signing secret and host password out of source control. The Supabase publishable key is designed to be public, but this app still keeps it server-side. For Vercel, configure `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `MARKET_SIGNING_SECRET`, and `HOST_PASSWORD` as environment variables, then redeploy. The host-console login reads `HOST_PASSWORD` server-side; update it in Vercel's environment settings to reset that password. `vercel.json` selects the Mumbai (`bom1`) region.

## Project layout

- `app/components/trader.tsx` — participant market, portfolio, news desk, charts, and audience wall.
- `app/components/host-console.tsx` — host controls, news selection, and participant session view.
- `src/game/catalog.ts` — fictional companies, starting prices, and the direction-checked economy, sector and company news catalog.
- `src/game/engine.ts` — market ticks, trades, news effects, account valuation, and session settlement.
- `src/game/store.ts` — shared Supabase market state, plus a separate in-memory store for local UI previews.
- `src/game/types.ts` — shared market and participant types.
- `src/ui-options.ts` and `app/ui-preview/` — the versioned visual themes and their local preview pages.
- `supabase/migrations/` — database objects required by the shared game state.

The market state is stored as JSONB and shared across app instances through Supabase RPC calls. The game does not use real-time exchange prices.

## Network behavior

The market keeps its one-second update rhythm and price rules unchanged. Unchanged snapshots return a small `304` response, charts send only new candles after their initial history load, inactive screens stop requesting chart candles, and host snapshots omit chart history. Company marks try to load small, lazy company favicon images and fall back to local initials if an image is unavailable; screens use system fonts. Disconnected or hidden terminals stop polling; transient request failures back off automatically before retrying.
